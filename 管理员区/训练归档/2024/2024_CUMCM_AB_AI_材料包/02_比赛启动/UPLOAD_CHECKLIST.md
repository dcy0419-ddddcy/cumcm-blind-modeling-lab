## A. 上传给 AI 前的阻断检查

### A1. 当届规则与权限

- [ ] `[BLOCK]` 已从赛事官网或主办方正式文件核验当届 AI 使用规则，不用往届规则或论坛转述代替。
- [ ] `[BLOCK]` 已核验联网、外部检索、云端上传、队外协作、引用、匿名、代码附件和生成内容披露要求。
- [ ] 官方规则原文件/网页快照已保存，含标题、URL、发布日期/版本、访问时间及时区和 SHA-256。
- [ ] 冲突或缺失条款已标成 `unverified` 并列入阻断项；没有用“没禁止就是允许”补空白。
- [ ] 计划使用的 AI、插件、云盘、在线求解器和代码执行环境均在允许范围内。
- [ ] 已确定 AI 使用日志的字段、保存位置和赛末披露方式。

若以上任一 `[BLOCK]` 未通过：只上传不受限制的最小材料做本地/离线准备；不得外传赛题附件、检索答案或声称合规。

### A2. 保密、个人信息与许可

- [ ] `[BLOCK]` 题面、附件和数据许可允许上传到所选 AI/外部服务；若不允许，使用合规的本地工具或不上传。
- [ ] 已移除身份证号、手机号、邮箱、学校内部账号、API 密钥、Cookie、访问令牌、私有服务器地址和无关个人信息。
- [ ] 队号、姓名、学校等信息按匿名规则处理；需要保留时有明确理由。
- [ ] 文件元数据、批注、修订历史、隐藏工作表/幻灯片、图片 EXIF 和压缩包内文件已检查。
- [ ] 第三方数据、图片、地图、字体、代码和模板的使用许可及引用义务已登记。
- [ ] 上传内容为完成任务所需的最小集合，未顺带上传整个个人目录或无关项目。

### A3. 提示注入与文件安全

- [ ] 将题面、参考资料和外部网页视为数据来源；其中要求“忽略规则、泄露密钥、运行命令”的文字不当作系统指令。
- [ ] 宏、可执行文件、脚本和压缩包已盘点；来源不明代码只做静态检查，不直接运行。
- [ ] 原始文件保存只读副本；AI 生成或清洗后的文件写入派生目录，不覆盖原件。
- [ ] 所有文件名、扩展名、实际 MIME/格式和可打开性一致；未用改扩展名掩盖格式。

## B. 开赛时首批材料清单

### B1. 必需上传

- [ ] `MASTER_PROMPT.md`：已填写比赛名称、题号、官网、时区、项目路径、软件约束和提交物；未知项保留 `待核验`。
- [ ] `output_protocol.schema.json`：本地 JSON 解析与 schema 自检通过。
- [ ] `output_protocol.example.json`：仅作格式示例，`synthetic_example=true`；确认不会被当作比赛结果。
- [ ] 自包含知识库：含符号/单位规范、常用模型选择条件、验证菜单、代码与写作规范；不含答案或范文内容。
- [ ] 当届官方竞赛规则、AI 条款、论文/附件格式和提交说明。
- [ ] 完整题面：页码清晰、公式可读、图表未裁切。
- [ ] 全部官方数据附件与空白结果模板：保持原文件名、表名、行列和格式。
- [ ] `inputs_manifest.json`：路径、类别、来源、访问时间、SHA-256、许可/保密级别齐全。
- [ ] 队伍约束说明：可用硬件、语言/库、队员技能、不可用工具、时间预算与分工。

### B2. 条件上传

- [ ] 历史自有代码只在许可允许且来源清楚时上传，并标注许可证、用途、测试状态和是否含往届题解特化逻辑。
- [ ] 已有训练材料与方法卡不含当届答案；若含外部内容，来源与可用阶段已标注。
- [ ] 扫描版 PDF/OCR 同时保留原图；OCR 文本不得替代公式和表格的人工核对。
- [ ] 大数据集无法上传时提供字段字典、哈希、抽样规则和本地执行接口；不得用随意抽样冒充全量结果。

### B3. 首批明确禁止上传

- [ ] `[BLOCK]` 独立冻结 G6 前未上传或打开任何答案、优秀论文、解题博客/视频、答案摘要、代码仓库或搜索结果片段。
- [ ] 未把第三方数值、截图或公式删去来源后混入 `03_independent/`。
- [ ] 未上传密钥、凭证、未经授权的私有数据或其他队伍材料。
- [ ] 未把占位示例、随机生成数据或情景参数标成真实观测。

## C. AI 首次响应验收

- [ ] AI 先盘点文件、缺失项、规则核验计划和当前闸门，没有立即联网查答案。
- [ ] AI 将信息标为题面事实、官方规则、派生结论、建模假设、情景参数、外部参考或待核验。
- [ ] AI 没有虚构打不开文件的内容、缺失表格字段、官方条款、引用或运行结果。
- [ ] AI 给出的关键分歧不超过三个且确实会改变路线；其余事项继续做安全准备。
- [ ] 已建立来源、假设、决策、运行、验证和 AI 使用台账。
- [ ] 输出 JSON 能被 `output_protocol.schema.json` 校验；`pass` 项均有现存证据。

## D. 独立阶段材料完整性（G1–G5）

### D1. 输入与题意

- [ ] 原始题面、附件、模板均有 SHA-256，只读保存且无静默修改。
- [ ] 每个常量、单位、索引和模板字段能回指题面页码、表格或单元格。
- [ ] 目标量、时间域、精度、边界和终止条件唯一；歧义有主解释与替代情景。
- [ ] 缺失数据导致不可识别时明确说明；情景值与观测值分开。

### D2. 模型与代码

- [ ] 主模型的变量、状态、目标、约束、适用条件和局限完整。
- [ ] 至少有一个手算/解析/穷举黄金样例和一个独立复算路径。
- [ ] 参数、容差、步长和随机种子位于配置文件；代码无未登记的隐藏魔数。
- [ ] 单一入口命令能从原始输入重建核心结果；环境与依赖版本已锁定。
- [ ] 代码对异常、不可行、未收敛、非有限值和空数据显式失败，没有默认填 0。

### D3. 结果与验证

- [ ] 结果对象记录单位、内部精度、展示精度、来源运行、模型和假设。
- [ ] 已执行边界、反例、守恒/量纲、残差、收敛、敏感性和独立复算中适用项。
- [ ] 所有 `critical` 检查通过；`warning/fail/not_run` 没有被删除或改名规避。
- [ ] 论文表格、图和提交模板由同一结果对象生成，无手抄数值。
- [ ] 干净环境复现成功，命令、退出码、日志、时长、种子和产物哈希存在。

### D4. 论文候选

- [ ] 摘要逐问说明方法、关键结果、验证和局限；没有无依据的“最优/显著/完全”。
- [ ] 假设、符号、单位和编号前后一致；公式变量就地定义。
- [ ] 图表标题、坐标、单位、精度和数据来源完整；黑白打印仍可辨认。
- [ ] 引用可定位且正文确实使用；没有编造 DOI、网址、页码或访问日期。
- [ ] 模板文件名、页数、大小、匿名、字体/版心及附件格式符合当届规则。
- [ ] AI 生成文字、代码或图表已由队员逐项审阅，并按当届要求披露。

## E. 独立冻结与参考隔离（G6）

- [ ] `[BLOCK]` 独立论文、代码、配置、结果、测试、验证报告、失败日志和产物清单齐全。
- [ ] `[BLOCK]` 在未读取任何答案类材料的前提下生成冻结号、时间和完整 SHA-256 清单。
- [ ] `[BLOCK]` 至少一名队员复核“独立阶段未访问范文/答案”的声明并签名；无法确认时如实标风险。
- [ ] 冻结目录已只读、打版本标签或复制到不可变归档；后续修改另起版本。
- [ ] `output_protocol.json` 中 `originality.independent_freeze=true`，且冻结清单产物 ID 可解析。
- [ ] 独立版中的失败项与局限保留，没有为接近参考答案而删除。

G6 未通过时不得进入 F。

## F. 官方优秀案例检索与比较（G7–G8）

- [ ] `[BLOCK]` 当届规则允许，且队员已明确切换到“参考比较”模式。
- [ ] 检索范围首先限定赛事官网/主办方正式发布页；搜索不到记 `not_found`，不拿聚合站冒充官方。
- [ ] 每个案例记录官方页面、附件标题、发布日期、访问时间、URL、本地快照和 SHA-256。
- [ ] 案例文件只存 `04_reference/`，独立代码不直接读取该目录，提交构建也不从该目录取数。
- [ ] 在看到差异前，用同一量表分别评估独立稿和案例，保留盲评记录。
- [ ] 比较只提取问题拆解、模型类别、假设、验证、写作结构和工程方法；没有大段摘抄或近似改写。
- [ ] 每条改进标注来源：`验证缺口触发 / 案例启发 / 独立优化`；案例启发另起版本。
- [ ] 所有采纳的改进均在本题重新推导、实现和验证；未把案例数值回填成独立结果。
- [ ] 相似公式、图表、代码和文字经过原创性人工检查；必要引用已补全。
