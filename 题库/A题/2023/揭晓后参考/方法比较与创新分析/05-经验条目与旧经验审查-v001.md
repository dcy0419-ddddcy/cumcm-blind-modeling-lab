## 3. 实质修订记录

### X001：E001范围收窄

- **修改前原文要点**：改变未接收光线终点，净接收量不变但分项效率可变。
- **修改后解释**：只要实际接收事件与联合存活事件不变，N04不能作为总效率或总功率变化的直接原因；它只能影响阴影遮挡和截断的条件分解。

## 4. 新增经验条目

### E022 — 先区分“设计表达”与“搜索算法”

- **触发情境**：高维布局优化出现大量坐标、尺寸或分组变量，准备选择GA、PSO、网格搜索等算法时。
- **建议行动**：先设计能生成完整可行清单的低维表示，再比较搜索算法；单独记录表示限制和算法贡献。
- **机制解释**：结构化表示决定搜索能看到哪些设计和可行候选密度，往往比更换优化器更影响结果。
- **支持证据**：A0127第16—17页分区同心圆；A092第27—29页逐环规格；本解答Q2-A与Q3六组。
- **证据状态**：本题已观察+文献报告+机制支持；没有同评价器消融。
- **适用条件与代价**：变量有空间结构；代价是限制原可行域。
- **反例或失效边界**：真实优质设计高度不规则时，规则化表示会成为瓶颈。
- **验证方法或停止条件**：在同一评价器下比较两种表示的可行率、最好结果和成本；若扩大表示只增加噪声/不可行率而无可分辨改善，停止细化。
- **来源阶段**：揭晓后新增。

### E023 — 将可构造约束与后验全检配对

- **触发情境**：候选需要满足大量镜对距离、边界或禁布约束。
- **建议行动**：把主要约束写进生成规则以提高可行率，同时对展开后的实际清单做全量独立检查。
- **机制解释**：构造减少无效搜索，后验检查捕获跨环、舍入和实现偏差。
- **支持证据**：A0127环带构造及`pdist`检查；本解答所有正式清单全镜对读回核验。
- **证据状态**：本题已验证，机制清楚。
- **适用条件与代价**：约束具有几何结构；全检仍有二次复杂度，可用经过证明的空间索引加速。
- **反例或失效边界**：只检查生成参数、只检查同环或只检查最近若干镜不满足规则。
- **验证方法或停止条件**：对最小余量、边界和舍入后清单做穷举；任一漏判即停止使用生成器输出作为可行证据。
- **来源阶段**：盲解已有，揭晓后由A0127加强。

### E024 — 硬约束优化采用“可行性门—目标门”

- **触发情境**：目标是比值或效率，但必须先达到总量下限。
- **建议行动**：无可行解时以约束缺口导航；得到可行基线后保留它，只接受在可行性证据下改善原目标的候选。
- **机制解释**：防止优化器通过缩小规模提高比值却失去下限，也防止把罚函数高分当真实可行。
- **支持证据**：C22失败→R023→R027；A0165Q2/Q3未达60 MW；A0127Q3达标但q低于Q2。
- **证据状态**：本题已验证+反例支持。
- **适用条件与代价**：存在明确硬约束；可能暂时牺牲目标，需保留多样可行基线。
- **反例或失效边界**：缺口函数与真实可行性不一致时，必须回到完整判定。
- **验证方法或停止条件**：所有拟提交候选通过冻结后的独立完整判定；未通过则回退，不换种子掩盖。
- **来源阶段**：盲解已有，揭晓后系统化。

### E025 — 小幅改进必须用配对比较与新确认分工

- **触发情境**：候选差值与随机评价波动同量级。
- **建议行动**：搜索阶段用稳定身份的共同随机数比较；候选冻结后用未参与选择的新随机流同时评价候选与基线，并分别检验额定和相对改进。
- **机制解释**：配对减少差值方差，新数据降低选择偏差；二者解决不同问题。
- **支持证据**：Q3F013相对R027的0.94995%改善及配对工作量；旧R027与新配对R027数值分开保存。
- **证据状态**：本题已验证，统计机制支持。
- **适用条件与代价**：对象可建立稳定对应；需要额外确认预算。
- **反例或失效边界**：镜数变化且无合理对象映射时，不可强行逐镜配对，可在更高层共享光源样本。
- **验证方法或停止条件**：差值不超过预登记工作量时报告不可区分；确认数据一经用于调参即失去独立身份。
- **来源阶段**：盲解已有，揭晓后加强。

### E026 — 增加自由度不等于得到更好解

- **触发情境**：从统一参数升级到分组或逐镜参数。
- **建议行动**：始终保留原可行基线，使用相同口径比较；若新搜索未改善，先检查参数化和搜索覆盖，不能断言新自由度无用。
- **机制解释**：可行域变大只保证理论最优值不差，有限算法可能因维度、噪声和预算得到更差方案。
- **支持证据**：A0127 Q3的q低于其Q2；本解答Q3只在6组子空间获得0.95%。
- **证据状态**：文献报告+本题已验证的机制实例。
- **适用条件与代价**：比较必须同评价口径；保留基线会占用部分评价预算。
- **反例或失效边界**：若评价模型或约束改变，旧基线需先重评，不能直接比较。
- **验证方法或停止条件**：对每次增加自由度设置基线回归和最小可分辨改善；无改善且成本陡增时回退。
- **来源阶段**：揭晓后新增。

### E027 — 参考结果用于提出假设，不直接证明方法优越

- **触发情境**：优秀论文报告值明显更好，但模型、清单或代码不完整。
- **建议行动**：先对齐定义和约束；把“报告值更好”“同模型下更好”“确实可行”分开，缺清单时只形成待检验的机制假设。
- **机制解释**：设计质量、评价口径和实现误差会共同影响最终数字。
- **支持证据**：A092高q但无完整清单；A0127触地边界；A0165未达额定。
- **证据状态**：本题对照已验证。
- **适用条件与代价**：跨论文比较；需要额外口径表和可能的重评成本。
- **反例或失效边界**：若官方提供统一评价器和完整清单，可直接同口径比较。
- **验证方法或停止条件**：没有同评价器或严格可比定义时，不把差距归于单一算法。
- **来源阶段**：揭晓后新增。

### E028 — 验证证据必须标注所支持的结论层级

- **触发情境**：同时有解析测试、随机批次、重建核验和物理假设。
- **建议行动**：每项验证明确“检查对象—支持结论—不覆盖范围”。
- **机制解释**：避免用同一批统计的恒等式证明物理正确，或用文件一致性证明模型正确。
- **支持证据**：本解答四层证据；参考论文多以趋势图或随机可行解支持过强结论。
- **证据状态**：本题已验证+反例支持。
- **适用条件与代价**：所有复杂计算；增加少量记录成本。
- **反例或失效边界**：没有独立预期的测试只能作为回归，不能称独立验证。
- **验证方法或停止条件**：交付前扫描“准确、证明、可靠、最优”等词，要求逐项证据映射。
- **来源阶段**：盲解已有，揭晓后强化。

### E029 — 结果必须绑定生成路径，而非只绑定最终文件

- **触发情境**：论文附有多套代码、搜索路径或中间参数。
- **建议行动**：为每个正式结果保存输入设计、算法入口、配置、代码哈希、随机流、原始统计、导出文件和重建关系。
- **机制解释**：代码存在不表示它生成了该表；版本谱系可以防止把示例、绘图脚本或失败候选当正式结果。
- **支持证据**：本解答冻结和清单重建；A092正文与附录路径难以完全对应。
- **证据状态**：本题已验证+文献反例。
- **适用条件与代价**：多阶段数值项目；增加自动化元数据维护。
- **反例或失效边界**：简单手算仍需保存输入和推导，但不需要复杂哈希体系。
- **验证方法或停止条件**：无法从结果文件追到唯一入口时，结论降级为不可复现报告值。

### E030 — 先做信息价值高的计算，再做机械交付核验

- **触发情境**：计算和人工时间有限，既要搜索、确认又要生成大量追溯文件。
- **建议行动**：优先执行会改变模型、候选或可行判定的检查；确认结果稳定后再集中做排版、哈希和索引，尽量自动生成。
- **机制解释**：过早高精度确认和重复文档修复会挤压设计探索，但确认预算又不能被搜索耗尽。
- **支持证据**：Q2首轮C22高等级确认失败、后续搜索范围有限；多次自引用/表格识别修复没有改变数值。
- **证据状态**：本题流程观察，机制支持；尚未跨题验证。
- **适用条件与代价**：阶段授权允许在阶段内调整顺序；不能跳过用户要求的门禁或必要冻结。
- **反例或失效边界**：关键版本未先冻结时，延后记录会损失证据，故最小配置/决策仍须实时保存。
- **验证方法或停止条件**：下题记录决策性计算、确认、机械核验三类用时；若自动化降低了遗漏而不影响追溯，则保留。
- **来源阶段**：揭晓后新增。

## 5. 不应推广的结论

1. 不能从本题推出蒙特卡洛一定优于确定性求积；选择取决于维度、边界复杂度和误差要求。
2. 不能从A092报告值推出遗传算法一定优于结构化遍历；算法贡献没有消融。
3. 不能从Q3F013推出缩小镜高通常提高单位面积功率；这是固定布局、特定分组的结果。
4. 不能把“100个随机解均较差”推广为全局最优证据。
5. 不能把本题三问当成三个独立问题来满足跨题验证。
6. 不能把参考论文获奖或展示身份当作公式、约束和代码无误的证明。
