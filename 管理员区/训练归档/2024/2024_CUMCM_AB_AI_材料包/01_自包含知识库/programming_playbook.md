# 编程与复现手册

## 一 单一事实源

模型参数、索引、单位和容差只定义一次。程序把结构化结果写入 CSV/JSON，论文表格、图和官方模板从这些结果生成，禁止在三个地方手工录入同一数字。每个结果对象至少记录 `value`、`unit`、`precision`、`model_id`、`run_id` 和 `assumption_ids`。

## 二 推荐目录与入口

```text
project/
  inputs/raw/          # 原始题面与附件，只读
  src/                 # 纯模型和通用算法
  tests/               # 单元、边界、回归测试
  configs/             # 参数、容差、随机种子
  results/             # CSV/JSON，程序生成
  figures/             # 由 results 生成
  submission/          # 官方模板或最终论文
  logs/                # 命令、版本、耗时、失败记录
  run_all.py           # 单一复现入口
```

入口应从原始输入重建核心结果，遇到空数据、非有限值、不可行或未收敛时显式失败。缓存只能提速，不能成为唯一数据源；禁用缓存后仍应可复现。

## 三 数值算法纪律

- 求根：先建立有符号残差和可靠括区，再用有界算法；记录括区、容差、迭代和最终残差。
- 优化：先穷举/网格得到基线，再局部优化；检查边界、多个初值和参数两侧。
- 微分：能解析微分则优先解析；有限差分同时做步长加密。
- 积分/仿真：至少两档步长或容差，比较关键输出而非只看“程序成功”。
- 随机算法：固定并记录种子；多种子报告分布，不挑最好一次。
- 概率：优先对数域计算似然与尾概率，避免下溢；检查概率和为 1。

## 四 决策枚举与状态机

二元动作少时，用位串或命名字段穷举全部策略，并为每条策略返回“可行/不可行原因、期望成本、期望收益、关键流量”。不要只保存最优行；完整策略表是发现成本漏项和并列最优的证据。返工循环使用显式状态转移或更新方程，测试吸收概率和期望访问次数。

## 五 测试金字塔

1. 单元测试：几何距离、概率归一、成本分解等局部不变量。
2. 黄金样例：可手算的小实例或退化边界。
3. 端到端测试：入口命令生成全部必需文件。
4. 回归测试：关键数值在容差内稳定，文件结构和字段不变。
5. 性质测试：单调性、对称性、守恒、上下界。
6. 交叉实现：关键结论用另一公式、库或小规模穷举复算。

测试“通过”只在测试实际运行、退出码为零且日志存在时填写。不能运行就标 `not_run`，不得凭阅读代码宣称通过。

## 六 Excel 与提交附件

先复制官方空白模板，再原位写值；不得重建工作簿导致表名、合并单元格或格式丢失。写入后必须重新打开，检查：

- 工作表名和顺序；
- 标签、行列、时间点/对象索引；
- 数字类型、单位、小数位和空值；
- 公式错误字符串；
- 起始、中间、末尾范围；
- 渲染后的截断、乱码、溢出和隐藏列行。

模板内容必须与结构化结果逐项比对，不以肉眼看起来“差不多”为准。

## 七 性能与接管

先测正确性，再优化瓶颈。保存粗略复杂度、实测耗时和内存。长任务持续写日志与中间检查点；任何队员都能通过 README 里的一个命令接管。赛末保留最后一次成功运行的环境版本、命令、退出码、运行时长和产物哈希。
