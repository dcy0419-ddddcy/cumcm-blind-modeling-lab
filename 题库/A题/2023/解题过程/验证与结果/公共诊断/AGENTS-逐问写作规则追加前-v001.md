# Codex 工作约束

本文件是“26国赛”项目级长期规则，适用于本项目后续任务；不是操作系统环境变量，也不修改其他项目的设置。管理员导出单题时必须携带本文件的当前版本。

## 工作范围

- 盲解任务只能读取当前单题盲解工作区中的题目、附件、方法资料和提示词。
- 不得读取父目录、兄弟目录、年度题库、管理员映射、Git 历史中未明确授权的揭晓后材料。
- 不得访问互联网，也不得使用网页搜索、浏览器、外部论文数据库、GitHub 搜索或远程代码搜索。
- 不得检索题目标题、题目原句、竞赛年份、既有答案、代码、博客、视频或优秀论文。
- 如果完成任务必须依赖外部事实，先记录为“外部依赖”，说明影响，并等待用户决定；不得自行联网补齐。

## 允许资料

- 当前题目 PDF 与附件。
- 用户提前提供的数学建模方法库。
- 非目标年份的优秀论文，但仅限赛前写作与方法规范学习阶段；进入单题盲解工作区后默认不可访问。
- 本题在盲解过程中由自己产生的代码、图表、数据和 Markdown 记录。

## 分阶段执行

### 每题开始前的方法库检查

- 以 Datawhale《数学建模导论》为主方法来源，但只能读取当前单题工作区内已审核、固定版本的本地方法资料；原始教程及在线链接不属于盲解期间的自动授权资料。
- 每次开始新题，先检查方法库版本、资料清单、审核状态和方法索引；完成题目理解后，逐问阅读相关方法卡及验证规范，再提出候选方案。
- 在当前单题工作区的 `工作记录/方法库查阅记录.md` 中记录：实际阅读的本地文件与版本、适用条件、候选方法、排除理由、验证计划和资料缺口。不得在仅阅读索引时声称已读完正文。
- 每问选型前再次核对相关方法的前置条件；不为套用主教程的方法而改变问题定义。
- 若本地只有来源链接或 README、正文未导入或未审核，明确报告资料缺口，不冒充已学习，不自行联网。题面完整时可先进行材料审计和题目理解；进入方法学习、候选方案或求解前，等待用户补充资料或明确允许基于现有知识继续。
- 以上检查不改变原有阶段验收与用户确认要求，也不允许读取目标题解或其他隔离资料。

### 执行顺序

1. 先完成题目整体理解、逐问重述、符号和题间依赖，不立即求解。
2. 对每一问循环执行：候选方案 → 选型 → 建模 → 求解 → 验证 → 记录 → 阶段检查。
3. 前一问未达到验收标准时，不进入下一问；如后问反馈暴露前问缺陷，回滚并记录原因。
4. 全部问题完成后再统一做摘要、论文结构、图表和全局一致性检查。
5. 盲解版本冻结后，才允许加载当年优秀论文进行复盘。
6. 方案构造、建模求解、验证修订分别按用户指定阶段执行；仅同意“构造思路”不代表同意直接编码求解。每阶段保存记录并汇报后停止，等待用户确认。

## 记录规范

- 不输出或保存模型不可验证的隐藏思维链。
- 必须保存可审计的推理摘要：问题定义、假设、候选方法、取舍理由、关键公式、参数来源、计算证据、失败尝试、验证结果和不确定性。
- 代码、数据处理和图表必须可复现；记录环境、入口命令、随机种子和输出位置。
- 任何结论都区分：题目给定、合理假设、计算结果、经验判断和待验证猜测。
- 更新文档时保留原结论和修改原因，不得通过重写历史掩盖失败。

### 全流程 Markdown 追溯规则（v1.1）

以下路径均相对于当前授权的单题工作区。规则适用于材料检查、方法学习、题目理解、每问各阶段、论文整理及经授权的揭晓后复盘，不扩大阶段或资料访问权限。

#### 固定记录入口

- `工作记录/00-任务状态.md`：当前阶段、最新有效版本、完成状态、待确认事项、阻塞项和下一步。
- `工作记录/记录索引.md`：链接各阶段文件和证据，标记当前有效、已替代、已失效及待重新验证的版本。
- `工作记录/方法库查阅记录.md`：实际阅读文件、版本、审核状态、适用条件和资料缺口。
- `工作记录/阶段记录/`：独立阶段文档；例如 `S00-材料审计-v001.md`、`S01-题目理解-v001.md`、`Q01-方案构造-v001.md`、`Q01-建模求解-v001.md`、`Q01-验证与修订-v001.md`。后问依次编号。
- `工作记录/决策记录.md`：重要假设、方案选择和变更依据；使用连续决策编号，并链接所依据的阶段文件与证据。
- `工作记录/06-更新记录.md`：按时间追加修改原因、差异、证据与影响范围。
- `工作记录/归档清单.md`：阶段交付文件、代码、配置、图表、结果及相对路径；区分文件已保存、用户已验收、管理员已归档三种状态。
- 已有旧格式记录时先在索引中接续使用，不删除、不重复建立两套互不关联的历史；只有获准进入的阶段才能填写实际内容。

#### 写入时点与内容

- 每阶段结束、重要方案采用或否决、有意义的计算或验证完成、发现需回滚的问题、等待用户或结束回复之前，均须保存当前进度；不得只在聊天中输出，也不得等全题完成后凭记忆补写。
- 记录本阶段目标与验收标准、输入与资料版本、事实和假设、候选与取舍依据、关键推导和参数来源、代码及计算证据、验证结果、失败尝试、不确定性与下一步。
- 没有开展的事项写“未开展”；受阻或未完成的阶段不得标成已验收。无法确定失败原因时区分观察现象与待验证的原因。
- 文档链接对应代码、输入、环境、运行命令、随机种子和结果；复杂公式应可渲染。不要为记录而编造工具输出或隐藏思维链。

#### 版本保留

- 正在编写的草稿可编辑。已向用户交付的阶段，或关键假设、模型、参数、结果、结论发生实质变更时，保留旧版本并创建后续版本，说明替代关系。
- 当前状态和索引可以更新，但变更日志只追加；失效版本不得继续被引用为有效结论。
- 旧结论对应的关键代码、配置与结果也要保留可复现版本，不能仅保留旧文字。原始附件和冻结的盲解版本不得覆盖。
- 管理员归档后的 Git 历史是额外保障，不代替单题工作区内可直接读取的历史文档；盲解模型不访问 Git 历史找资料。

#### 修改前回读与影响追踪

1. 先读任务状态、记录索引、待改阶段当前版本、相关旧版本与决策记录，以及依赖该结论的后续阶段；只回读相关材料。
2. 定位原文件、版本和小节，说明原结论及当时依据；找不到依据时写“原依据记录不足，无法确认”，不得补造理由。
3. 区分题意、数据、假设、模型、代码、验证或表达问题；明确修改前后差异，不能仅写“已优化”。
4. 检查哪些后问接口、参数、代码、图表、结论和论文段落受影响；尚未复核的标为“待重新验证”，已知错误的标为“已失效”。
5. 执行与修改相匹配的检查，在用户授权范围内修订；超出当前阶段的修订先登记影响并请求用户确认，不擅自重做其他阶段。
6. 保存新版本，更新有效版本索引与日志；原始失败记录必须保留。

每次实质修改应记录：修改编号；涉及阶段；原文件、版本与位置；修改前内容；原依据；新问题或证据；修改后内容；修改理由；影响范围；重新验证的结果；未解决事项；新版本位置。

#### 阶段结束验收

- 确认文件确实写入，回读关键内容，核对证据文件及链接存在，当前有效版本和下游影响状态一致。
- 若没有写入能力或保存失败，明确报告“文件尚未保存”，不能把聊天文本当作已落盘文件。
- 汇报阶段摘要、文件与版本、重要变化、验收结果与待确认事项、下一阶段建议，然后停止。
- 每阶段可交管理员复制归档，但归档不等于用户验收。盲解模型不连接 GitHub、不查真实年份，不把带年份的目标路径写回匿名工作区。
- 揭晓后复盘另建版本，区分独立结论与参考论文后新增认识；总经验仅在获授权的复盘环境更新。

## 经验更新

- 先更新当前题目的 `经验.md`。
- 只有在至少两个不同题目中得到支持，或有清晰机理与反例边界时，才建议写入 `总经验/总经验.md`。
- 每次更新总经验前，必须检查旧经验是否存在适用范围过宽、证据不足、相互矛盾、不可执行或不可验证的问题。
- 每次更新总经验后，追加 `总经验/变更日志.md`，记录新增、修改、废弃、证据和影响范围。
